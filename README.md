# tinyAgentAccess

[![CI](https://github.com/letsopen-ai/tinyagentaccess/actions/workflows/ci.yml/badge.svg)](https://github.com/letsopen-ai/tinyagentaccess/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

An open-source, self-hostable, local-first Rust rebuild of the Amazon WorkSpaces for AI agents MCP server. AWS-compatible native tool names, running on your own computer, with no AWS dependency.

**v0.1.1:** desktop capture/input, sequences, forwarding, dialect adapters, local replay and human Stop.

**Security: no authentication. Binds to localhost by default. Do not expose this server to a network or the public internet. Wildcard binds are rejected; concrete non-loopback binds warn. Host/Origin checks are not authentication.** Security: see [SECURITY.md](SECURITY.md).

**Not affiliated:** tinyAgentAccess is an independent project, not affiliated with,
endorsed by, or associated with Amazon Web Services or Amazon. "Amazon", "AWS",
"Amazon WorkSpaces", and related names are trademarks of Amazon.com, Inc. or its
affiliates. Compatibility is a local reimplementation from public documentation
and the MIT-0 sample; this is not an official AWS product.

| Area | Status |

| Linux Wayland | Experimental; unverified on real GNOME/KDE sessions |

| Windows | Compiled / CI; GUI untested |

### Current limitations / known issues

- Tk and some window client areas may capture blank on macOS while the title bar remains visible.
- Retina, multi-monitor, denied-permission, and real GNOME/KDE Wayland behavior are not fully verified.
- Dialect schemas and forwarded-tool behavior with an unknown interface header are provisional.
- AWS mid-sequence Stop semantics are unknown; local sequences check Stop between steps.
- Run at most one capturing tinyagentaccess server per macOS desktop session. In a real-Mac isolation run (2026-11-24, loopback only), repeated and overlapping captures in one process were reliable, and a second server that was only listening did not interfere. Once a second process attempted a capture after another had already captured, that attempt hit the 10 s ScreenCaptureKit timeout (`ScreenCaptureKit capture timed out after 10 seconds`), and later captures in both processes timed out until both were restarted; after both test processes were stopped, a fresh single server captured normally. The same pattern held in reverse order. This is a documented local deployment limitation, not a proven tinyagentaccess code bug, and the failing Apple API stage was not isolated; there is no in-tree fix or cross-process lock.

### Release archives

Releases provide Linux/macOS `.tar.gz` archives and a Windows x86_64 MSVC `.zip`.
Each includes `THIRD_PARTY_LICENSES.html`, generated by cargo-about with full
dependency license texts. Verify the download against `SHA256SUMS` and its
Sigstore bundle using cosign; archives and the standalone license bundle also
have `.sigstore.json` signatures. For example:

```sh
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/letsopen-ai/tinyagentaccess/.github/workflows/release.yml@refs/tags/v0.1.1" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
```

On macOS, use `shasum -a 256 --ignore-missing -c SHA256SUMS`. In PowerShell,
use `Get-FileHash .\tinyagentaccess-x86_64-pc-windows-msvc.zip -Algorithm SHA256`
and compare the hash with `SHA256SUMS`. Windows binaries are not Authenticode-signed
(SmartScreen may warn); Windows support is compiled / CI checked, with GUI untested.

### Build and run from source

Install Rust 1.88+ (edition 2021), clone this repository, and run from its root.
See [permissions](docs/permissions.md) and [testing](docs/testing.md) for OS setup.

```sh
cargo run -p tinyagentaccess -- serve
# Optional: --config config.example.toml --bind 127.0.0.1:8765
cargo run -p tinyagentaccess -- print-config
```

### macOS first run

macOS Screen Recording and Accessibility permissions belong to the host app (the terminal or app that launches the server), not to a Rust source file. A new binary path or a new binary may need a new grant. The release and source builds are not notarized, so macOS may show Gatekeeper / unidentified-developer warnings.

Before starting the server, check what macOS will see:

```sh
tinyagentaccess doctor
tinyagentaccess doctor --json
```

`doctor` is read-only. It reports the version, the absolute path and SHA-256 of the running binary, the parent process chain with a guess at the host app, SSH / non-GUI hints, a remedy, and on macOS the no-prompt Screen Recording and Accessibility preflight results and whether ScreenCaptureKit is available. It never prompts, never opens System Settings, never reads `TCC.db`, never changes grants, and does not capture, post input, or bind a port. Exit code 0 means the checks passed or do not apply on this OS, 1 means a macOS permission preflight failed, and 2 means a usage or doctor error. With `--json`, stdout is a single JSON object.

After granting access, quit and restart the host app and then the server. Capture needs an unlocked interactive desktop; an SSH or other non-GUI session may not see the logged-in desktop. See [permissions](docs/permissions.md#macos).

### OpenCode (loopback)

Start the server first, then point OpenCode at its `/mcp` endpoint:

```sh
tinyagentaccess serve   # listens on 127.0.0.1:8765
```

Add this to your OpenCode config (for example `opencode.json`). The shape follows the official [OpenCode MCP server docs](https://opencode.ai/docs/mcp-servers/): `mcp.servers.<name>` with `"type": "remote"` and an absolute Streamable HTTP `url`. The name `taa` is only a label.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "taa": {
        "type": "remote",
        "url": "http://127.0.0.1:8765/mcp",
        "oauth": false
      }
    }
  }
}
```

- OpenCode's docs say remote servers use OAuth by default and document `"oauth": false` to disable it. tinyAgentAccess has no authentication, so `"oauth": false` is appropriate here.
- **This server has no authentication. Keep it on loopback** and do not point OpenCode at a non-loopback address.
- Tested with OpenCode v2.1.2 in Code Mode against a scratch loopback port (18776; the default 8765 is documented above). OpenCode exposed the tools as `tools.taa.agentaccess___...`, using the configured server name `taa`. In the same test, direct-list mode (`codemode: false`) did not expose usable tools even though the server showed as connected, so Code Mode is the tested path.
- OpenCode does not ship an official tinyAgentAccess template; this is a user-side config. Other OpenCode options (timeouts, headers, and so on) were not tested.

Stateful curl smoke test (requires Python 3 to extract the session header):

```sh
curl -sS -D /tmp/taa-headers -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}' \
  http://127.0.0.1:8765/mcp
TAA_SESSION=$(python3 -c 'print(next(x.split(":",1)[1].strip() for x in open("/tmp/taa-headers") if x.lower().startswith("mcp-session-id:")))')
curl -sS -H "Mcp-Session-Id: $TAA_SESSION" -H 'MCP-Protocol-Version: 2025-11-25' \
  -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","method":"notifications/initialized"}' http://127.0.0.1:8765/mcp
curl -sS -H "Mcp-Session-Id: $TAA_SESSION" -H 'MCP-Protocol-Version: 2025-11-25' \
  -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' http://127.0.0.1:8765/mcp
curl -sS -H "Mcp-Session-Id: $TAA_SESSION" -H 'MCP-Protocol-Version: 2025-11-25' \
  -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"agentaccess___wait","arguments":{"duration":0.001}}}' http://127.0.0.1:8765/mcp
curl -sS -i -X DELETE -H "Mcp-Session-Id: $TAA_SESSION" -H 'MCP-Protocol-Version: 2025-11-25' http://127.0.0.1:8765/mcp
```

Run SDK interop against the running server by installing `mcp==2.1.1` in a virtual environment and running `python scripts/interop_python_sdk.py --url http://127.0.0.1:8765/mcp`. It tests both legacy/stateful and 2026-07-28/stateless modes.

Desktop requirements:

- **X11:** run inside the graphical session with `DISPLAY` and Xauthority access. Uses pure Rust x11rb, XTest input, RandR primary monitor and GetImage capture. No Xlib/libxcb development packages.
- **Wayland (experimental):** install xdg-desktop-portal plus the GNOME/KDE backend. Approve Screenshot and RemoteDesktop access, selecting your primary monitor. Persistent consent tokens are stored with mode 0600 under `$XDG_STATE_HOME/tinyagentaccess/portal-restore-token` (default `~/.local/state/...`). Capture uses the Screenshot portal, without libpipewire; use a **single-monitor session** for now because that API may return the entire desktop. Known Screenshot/RemoteDesktop ratio mismatches fail before pointer injection; equal ratios cannot prove monitor identity. The portal cannot force primary-monitor capture or reliably honor `include_cursor=false`/`true`. Portal Unicode delivery still requires compositor testing. Consent waits are bounded to 60 seconds; cached session info stays available.
- **macOS:** grant Screen Recording and Accessibility to the terminal/app launching the server, then restart it. ScreenCaptureKit screenshots on macOS 14+ and CGEvent input are intended to preserve Retina pixel/point mapping; Retina behavior is not fully verified. The binary requires macOS 12.3+; when the screenshot class is absent, capture uses a dynamically resolved legacy CoreGraphics API if available. tinyagentaccess never requests a permission prompt; macOS 15+ may show its own periodic Screen Recording confirmation.
- **Windows:** GDI primary-display capture and DPI-aware SendInput. Use an unlocked interactive desktop. UAC/secure desktop and higher-integrity windows cannot be controlled. Code is cross-compiled here; GUI validation is still needed.

M2 targets the **primary display only** (Wayland currently requires one display). Default images are 1280×720, aspect-preserving with centered black bars; clicks in bars clamp to the display edge. Native mode returns physical capture dimensions. All desktop operations run in blocking workers. PNG and JPEG are supported. See [keys](docs/keys.md), [permissions](docs/permissions.md), [testing](docs/testing.md) and the [design limitations](docs/design.md).

Linux auto selection prefers Wayland whenever `WAYLAND_DISPLAY` or `XDG_SESSION_TYPE=wayland` is present, even when `DISPLAY` also exists: XWayland XTest cannot control native Wayland windows. Override with `[platform] linux_backend = "auto" | "wayland" | "x11"`. With no graphical session the server starts and desktop calls return an actionable error. No TLS or C cross-compiler is required for Windows GNU type-checks.

Workspace: `crates/tinyagentaccess` (CLI), `crates/taa-mcp` (HTTP/session lifecycle), `crates/taa-tools` (config, registry, validation, dispatch), `crates/taa-platform` (typed desktop boundary, shared images/keys, OS backends and an opt-in `test-support` recording mock).

See [verified AWS parity facts](docs/aws-parity.md), [design and compatibility decisions](docs/design.md), and [example config](config.example.toml). Validate with `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace`.

Wildcard binds (`0.0.0.0` / `::`) are rejected because this server has no authentication. Use the loopback default or an explicit concrete IP; non-loopback binds emit a no-auth warning and only that IP or loopback Host values are accepted.

Local screenshot saving is optional and disabled by default:

```toml
[screenshots]
save_dir = "" # disabled; otherwise set an absolute private directory
```

Returned standalone and sequence terminal images are saved under `agentaccess/screenshots/year=YYYY/month=MM/day=DD/{session-id}/` using UTC epoch-millisecond filenames and the real PNG/JPEG extension. Unix directories/files use 0700/0600 when created; Windows inherits directory ACLs. Save failures warn on stderr and leave tool results intact. Relative save paths are rejected. No cloud upload occurs.

### MCP tool forwarding

Set `[agent_access] forward_mcp_tools = true` and optionally set
`[forwarding] config_path = "/absolute/path/redirection.json"`. The redirection file
must be UTF-8 without a BOM:

```json
{"mcpServers":{"example":{"command":"/absolute/path/mcp-server","args":["--stdio"]}}}
```

Only stdio is supported. Children inherit the server environment; `env`, `cwd` and
other unknown keys are ignored with warnings. Tools appear as
`forwarded___example___<tool>`. Lists and calls have a five-second timeout. Each MCP
session owns its children and closes them on session expiry or closure. Forwarding-only
operation (`computer_vision = false`, `computer_input = false`, forwarding enabled)
is supported. Empty config_path uses `/etc/dcv/mcp_server_redirection_config.json`
on Linux, `C:\ProgramData\NICE\dcv\mcp_server_redirection_config.json` on Windows,
and the provisional `/Library/Application Support/tinyagentaccess/mcp_server_redirection_config.json`
on macOS. See [design decisions](docs/design.md#mcp-tool-forwarding-m4).

Milestone 5 adds computer-use dialects selected per request with
`x-amzn-agentaccess-computer-use-interface-id`: `ANTHROPIC_COMPUTER_20250124`,
`ANTHROPIC_COMPUTER_20251124`, `ANTHROPIC_COMPUTER_TOOLSET_20260801`,
`OPENAI_COMPUTER_V1`, and `GOOGLE_COMPUTER_USE_3X_DESKTOP_V1`.
Send it on both tools/list and every tools/call. Omitted/empty selects native tools;
unknown values return JSON-RPC -32602. Dialects are **best-effort, unverified vs AWS**;
all schemas are **PROVISIONAL vendor-derived, not AWS-confirmed**. Only standard
desktop tools are replaced; session, wait, sequence and forwarded tools stay available.
See the [local conversion choices](docs/design.md#m5-computer-use-dialect-adapters).

### Local replay and human control (M7)

```toml
[replay]
enabled = true
save_dir = "/absolute/private/replay"
# max_bytes_per_session = 104857600 # optional frame-storage budget; default unlimited

[agent_access]
user_control_mode = "view_stop" # disabled (default) | view_only | view_stop
```

Replay captures a whole-screen image immediately before each desktop action, including
translated calls and individual sequence steps, using the configured PNG/JPEG renderer
and default cursor setting. Responses are appended after completion. Wait, session
metadata and forwarded calls have metadata only. Frames and append-only `events.jsonl`
live under `agentaccess/replay/year=YYYY/month=MM/day=DD/{mcp-session-id}/`.
Closure (tool, DELETE, idle expiry or Stop) writes an escaped local `index.html`.
These are **TINY-PROPOSAL local artifacts, not an AWS/Bedrock evidence report**;
there is no video, transcript, S3, KMS, or automatic retention deletion.
Replay can contain sensitive screen/text/tool data; enable only in a private directory
and remove it yourself. Unix creation modes are 0700/0600, Windows inherits ACLs;
symlink sink directories and existing output files are refused. Failures warn without
changing the tool result. The optional replay byte budget stops frame storage with one warning; metadata and the index continue and may exceed the budget. Opaque metadata is capped (see [M7 choices](docs/design.md#m7-local-replay-and-human-control)).

Open `http://127.0.0.1:8765/observe` on the same origin as the server. `view_only`
shows session selection and fresh screenshots; `view_stop` also shows Stop. `disabled`
returns 404 for observer routes. All local sessions share one desktop; selection
chooses which session to observe or close, not a separate OS desktop. Polling uses
the normal capture path and may require OS consent. Stop releases held input, ends forwarding, and
marks the session stopping immediately and closes it after the admitted action finishes. Sequences check Stop between steps (PROVISIONAL; AWS mid-action semantics unknown). Observation does not reset the idle timer. Queued calls
then fail like calls after normal closure. **TINY-PROPOSAL:** Stop closes only the
targeted MCP session; it is not a lockout and does not block new sessions. Legacy
transport sessions then get HTTP 404; the [MCP Streamable HTTP spec](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
requires clients to start a new session after a 404 for a request carrying
`Mcp-Session-Id`, so a client may re-initialize and continue without the agent
noticing. Modern-dialect calls with the stopped `mcpSessionId` return an
`Unknown mcpSessionId` tool error, and the agent may continue by calling again with
`mcpSessionId: "NEW"`. To keep an agent off the desktop, stop the agent/MCP client
or the tinyAgentAccess server. `user_control_mode` controls observation and Stop
availability, not agent access.
No `client_disconnected` notification is emitted: its AWS wire form is unknown.

The observer is an **unauthenticated local substitute, not AWS DCV**. Keep the bind
on loopback until authentication exists. Host/Origin checks and same-origin Stop
requests reduce browser abuse; they do not authenticate local users.
